## Формат отчета

Краулер возвращает JSON-отчет со сводной информацией о запуске и массивом найденных страниц:

```json
{
  "root_url": "https://example.com",
  "depth": 1,
  "generated_at": "2024-06-01T12:34:56Z",
  "pages": [
    {
      "url": "https://example.com",
      "depth": 0,
      "http_status": 200,
      "status": "ok",
      "error": "",
      "seo": {
        "has_title": true,
        "title": "Example title",
        "has_description": true,
        "description": "Example description",
        "has_h1": true
      },
      "broken_links": [
        {
          "url": "https://example.com/missing",
          "status_code": 404,
          "error": "Not Found"
        }
      ],
      "assets": [
        {
          "url": "https://example.com/static/logo.png",
          "type": "image",
          "status_code": 200,
          "size_bytes": 12345,
          "error": ""
        }
      ],
      "discovered_at": "2024-06-01T12:34:56Z"
    }
  ]
}
```

- `root_url` — стартовый URL анализа.
- `depth` — максимальная глубина обхода, заданная пользователем.
- `generated_at` — время формирования отчета в формате ISO8601.
- `pages` — массив страниц, попавших в отчет.
- `url` — абсолютный URL страницы.
- `http_status` — HTTP-код ответа страницы.
- `status` — краткий статус страницы: `ok` для успешных ответов и `error` для ошибок.
- `error` — сообщение об ошибке; пустая строка означает отсутствие ошибки.
- `seo` — наличие и значения основных SEO-элементов страницы.
- `broken_links` — массив ссылок, которые вернули ошибочный HTTP-код или не открылись.
- `assets` — массив найденных ресурсов страницы: изображений, скриптов и стилей.
- `discovered_at` — время обнаружения страницы в формате ISO8601.

Все ключи присутствуют в JSON всегда. Пустые значения передаются как пустые строки или пустые массивы.

## Глубина обхода

Настройка `depth` определяет количество уровней страниц, которые краулер может включить в отчет внутри исходного домена.

- Стартовая страница всегда имеет `depth = 0`.
- Ссылки, найденные на стартовой странице, имеют `depth = 1`.
- Ссылки, найденные на этих страницах, имеют `depth = 2`, и так далее.
- Если уровень следующей страницы превысит заданный лимит, краулер не добавит эту страницу в очередь обхода.

Примеры:

- `--depth 0` анализирует только стартовую страницу.
- `--depth 1` тоже анализирует только стартовую страницу.
- `--depth 2` анализирует стартовую страницу и внутренние страницы, на которые она ссылается напрямую.
- `--depth 3` дополнительно анализирует внутренние страницы, найденные на страницах с `depth = 1`.

Значение можно изменить CLI-флагом:

```bash
./bin/hexlet-go-crawler --depth 2 https://example.com
```

Обход выполняется только для страниц внутри исходного домена. Ссылки на внешние домены не добавляются в `pages`, но могут проверяться и попадать в `broken_links`, если целевой ресурс недоступен.

## Ограничение частоты запросов

Краулер может ограничивать глобальную частоту HTTP-запросов для всего процесса. Ограничение применяется ко всем HTTP-запросам анализатора, включая загрузку страниц и проверку битых ссылок.

Доступны два CLI-параметра:

- `--delay=200ms` задает фиксированную задержку между соседними HTTP-запросами.
- `--rps=5` задает целевую частоту запросов в запросах в секунду.

Примеры:

```bash
./bin/hexlet-go-crawler --delay=200ms https://example.com
./bin/hexlet-go-crawler --rps=5 https://example.com
```

Если указаны оба параметра, `--rps` имеет приоритет над `--delay`:

```bash
./bin/hexlet-go-crawler --delay=1s --rps=5 https://example.com
```

При использовании как библиотеки это же поведение настраивается полями `Options.Delay` и `Options.RPS`:

```go
opts := crawler.Options{
    URL:   "https://example.com",
    Delay: 200 * time.Millisecond,
    RPS:   0,
}
```

Если `Options.RPS > 0`, значение `Options.Delay` игнорируется. Если `Options.Delay` и `Options.RPS` равны нулю, ограничение частоты отключено, и запросы не замедляются искусственно.

## Повторные попытки

Количество повторных попыток настраивается CLI-флагом `--retries`:

```bash
./bin/hexlet-go-crawler --retries=2 https://example.com
```

Значение `--retries` задает именно количество повторов после первой попытки. Поэтому общее максимальное количество обращений к одному URL равно `retries + 1`.

Примеры:

- `--retries=0`: только первая попытка, без повторов.
- `--retries=1`: первая попытка и один повтор, максимум 2 обращения.
- `--retries=2`: первая попытка и два повтора, максимум 3 обращения.

При использовании как библиотеки количество повторов задается полем `Options.Retries`:

```go
opts := crawler.Options{
    URL:     "https://example.com",
    Retries: 2,
}
```

Повтор выполняется только для временных проблем:

- сетевой сбой или ошибка транспорта;
- HTTP `429 Too Many Requests`;
- HTTP `5xx`, например `500 Internal Server Error`, `502 Bad Gateway`, `503 Service Unavailable`.

Обычные клиентские ошибки `4xx`, кроме `429`, не повторяются. Например, `404 Not Found` сразу считается итоговым результатом проверки ссылки.

Если все попытки исчерпаны, в отчете фиксируется результат последней попытки. Для битых ссылок это означает, что в `broken_links` попадет последний полученный HTTP-статус или сообщение последней сетевой ошибки.

Между повторными попытками используется ненулевая задержка, чтобы не создавать бурст запросов. Если `Options.Delay` или `--delay` не заданы, применяется минимальная задержка по умолчанию.
